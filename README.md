# The Parma-Light Platform

This git repository contains an implementation of the Parma-Light platform. Parma-Light is a simple, experimental implementation of the platform published in

> Pintz, M., Becker, D., Mock, M. (2024). **PARMA: a Platform Architecture to enable Automated, Reproducible, and Multi-party Assessments of AI Trustworthiness**. In *Proceedings of the 2nd International Workshop on Responsible AI Engineering* (pp. 20–27).

## Introduction

Clone this repository from github, if you want to experiment with the platform and its sources.

- the branch `main` contains the current published version
- the branch `develop` contains a stable version, which will become `main` soon.
- the frontend is a web application served by the backend. Workflows are edited graphically (based on LiteGraph).
- the concepts and the definitions (nodes, workflows, ...) are described in `resources/APIDOC.md`. The reference of
  all REST endpoints and definitions is generated from the source code into `resources/generated/API-REFERENCE.md`
  (by `./admin.sh apidoc`).
- definitions of nodes, workflows, data and runs can also be uploaded from the command line with `./curl.sh`
  (see `./curl.sh help`).

Parma_light can be run on a local system (see next section) or packaged into a docker image and run in a container
(see the section after the next one).

## Using the Platform on a local system from the git repository

- a recent Python3, uv and docker installation are required. You need a shell that can run bash scripts.
- start the docker demon
- `uv sync` - install dependencies
- activate the virtual environment generated by `uv` (this is done for you, if you use Vscode and start a terminal):
  - Windows: `source .venv/Scripts/activate`
  - Linux/MacOS: `source .venv/bin/activate`
- `pytest test` - check that the setup is fine
- run the admin script `./admin.sh help`.
  If you get a "permission denied" error, you need to make the admin script executable: `chmod +x admin.sh`

The setup is complete now. You can start to work with the platform

- `./admin.sh images sklearn` and `./admin.sh images array` - you need Docker images to work with. Generate them.
  The domains are the directories in `test/container`.
- `./admin.sh init` - initialize the datastore (directories and files from the `store` section of `parma_light.yaml`)
- `./admin.sh server` - start the backend server in a terminal of its own. It listens on port `8080`.
- `./admin.sh init-datastore` - in **another** shell: upload users, nodes, workflows and runs from `test/test_cmds`
  for testing and demonstration. It uses `./curl.sh`, see `./admin.sh help` and `./curl.sh help`.
  The credentials are taken from an env file:
  - `.env_testsetup` - git-controlled, contains only the well known test credentials. This is the default.
  - `.env` - git-ignored, for the real passwords. Use it with `./admin.sh init-datastore -e .env`.
    Create it as a copy of `.env_testsetup` and change the passwords. Never commit it.
- open `http://localhost:8080` in a browser and log in, e.g. as user `sklearn` of the test setup.
  The lists of data, nodes, workflows and runs show the uploaded definitions. Workflows can be edited, run and
  their results inspected.
  If the backend runs on a remote server you are connected to by ssh, forward the port:
  `ssh -L 8080:localhost:8080 <user>@<server>` and open `http://localhost:8080` locally.
- in directories `test/test_cmds/**` a lot of node and workflow definitions are available to experiment with.
- terminate the backend by hitting `CTRL-C`.

## Running the Platform in a docker container

- `./admin.sh dood-build` - build the docker image `parma_light` containing the backend
- `./admin.sh server-dood` - run the image. The backend listens on port `8080`. It uses docker of the host
  ("docker outside of docker") to run the node containers. See `./admin.sh help` for the options and for
  the security implications of access to `docker.sock`.
