Please read the README.md of the parma_light git repository.
============================================================

Commands:
  help     get help (this text).
  
  init -c {path-to-yaml-property-file} 
    creates a setup of the datastore for parma light. The directories/files are taken from the [store] section
    of the yaml property file. The default for '-c' is 'parma_light.yaml'. The directories/files must NOT exist.
    If you want to re-initialize the datastore, please remove the old datstore first.
  
  server -c {path-to-yaml-property-file}
    starts the PARMA light backend server. Listens on port 8080. Run it in a terminal of its own.
    -c defines the path to the yaml-property-file, default is 'parma_light.yaml'

  server-dood -di {docker-image} -c {path-to-yaml-property-file} -debugpy
    run the docker image of the parma_light backend (typically generated by "dood-build"). Listens on port 8080. 
    -di      defines the (optional) name of the parma_light docker image, default is 'parma_light'
    -c       defines the (optional) path to the yaml-property-file, default is 'parma_light.yaml'
    -debugpy run in debug mode (optional)

  image {domain} {name} {version}
    'domain' is the name of a directory in 'test/container', in which all container of a group are assembled
    'name' should be the name of an image to be build and the name of a directory in the 'domain' directory
    'docker build' is called.
    'version' is the version of the tag created (for demonstration purposes almost always "1").

  images {domain}
    create all images for the 'domain' given. 'domain' is the name of a directory in 'test/container'.

  dood-build
    build a docker images containing the parma_light backend.

    Notes: If you get a permission error for docker.sock, on linux systems run the command
        chmod 666 /var/run/docker.sock
    This is a security problem. Use never in production systems! Read about 'dood' and 'dind' and the security implications.

  init-datastore -e {path-to-env-file} -c {path-to-yaml-property-file} {sklearn} {array} {bash}
    for easy testing and demonstration: uploads users, nodes, workflows and runs from 'test/test_cmds' to a
    running backend by calling curl.sh.
    -e      defines the (optional) env file with the credentials, it is sourced. Default is '.env_testsetup'
            (git-controlled, the well known test credentials). Use '.env' (git-ignored) for the real passwords.
            See curl_help.txt for the keys.
    -c      defines the (optional) path to the yaml-property-file, default is 'parma_light.yaml'.
            The port is taken from 'server.port', the host is always localhost.
    sklearn array bash: (optional) flags selecting the groups to upload (1 = yes, 0 = no), defaults are 1 1 0.
    Example: ./admin.sh init-datastore -e .env 1 0 0

  assess
    use uv to update the toml-file and uv.lock, then run
    - pip-audit to create the bill-of-materials checking vulnerabilities in file audit.json
    - pip-licences to create the bill-of-materials checking licenses of used packages
      in file licenses.md and licenses.json

  apidoc [--check]
    generate the API reference 'resources/generated/API-REFERENCE.md' from the source code: the REST endpoints
    from the Flask routes and their docstrings (src/parma/routes.py), the definitions from the JSON schema
    (src/parma/intern/schema-def-for-user-commands.json). Run it after changing routes or the schema.
    --check  don't write, exit code 1 if the file is not up to date. A unit test checks this, too.

  publish-new-version <version-for-parma-light-starting-with-v>
    create a new version of the parma_light docker image to docker hub. Pin this version in the git repo by a tag with same name
