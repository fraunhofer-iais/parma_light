Please read the README.md of the parma_light git repository.
============================================================

curl.sh calls the upload routes of the PARMA light backend from the command line, as the frontend does.
Every call logs in, uploads the content of one file, prints the JSON response and logs out.
The commands snakemake-gen and snakemake-run instead generate a Snakefile and run it.
Exit code 0 on success, 12 otherwise.

  curl.sh [options] <command> <file>

Commands (exactly one):
  user <file>
    add all users defined in <file>. Route /user/upload. Admin only, thus use it with '--admin'.

  data <file>
    add all data defined in <file>. Route /data/upload.

  data-file <file>
    add the plain <file> as data. Route /data/upload-file. No metadata is needed, the backend generates
    the data definition:
    - name: file name with '.' replaced by '_', e.g. my.data.csv -> my_data_csv.
      A name starting with a digit gets a leading '_', e.g. 1.csv -> _1_csv.
    - type "file", storage "platform", hash "true", format "any", user_path: the file name

  node <file>
    add all nodes defined in <file>. Route /node/upload.

  workflow <file>
    add all workflows (and refines) defined in <file>. Route /workflow/upload.

  run <file>
    execute all runs defined in <file>. Route /run/upload.
    Returns when the last run has finished, stops at the first failing run.

  snakemake-gen <workflow name>:<version>
    generate the Snakefile of a stored workflow and store it as data named
    'snakefile_<workflow name>_<version>'. Route /workflow/snakemake_gen. No upload.
    The version is required: a number or 'latest' (then the data name contains the version found).
    Only workflows with docker nodes can be exported. The response contains the hash, name and version
    of the data, not the Snakefile.

  snakemake-run <snakefile data name>:<version> [<cores>]
    run a Snakefile stored by snakemake-gen with Snakemake on the backend machine, using <cores> cores
    (default 1). Route /workflow/snakemake_run. Returns when Snakemake has finished. The response contains
    the stored run record (hash, name, version), the exit code and the last lines of the Snakemake output.
    Not available if the backend runs in a container.

  Running a Snakefile stores the outputs of every rule as data and at the end a run record with the run
  log (property "_executor": "snakemake", runs started by 'curl.sh run' have "_executor": "builtin") in
  PARMA. The run is named 'run_snakefile_<workflow name>_<version>', the log of Snakemake itself is stored
  in the run record as "_log_snakemake". If you run
  a Snakefile yourself (e.g. 'snakemake --cores 4 -s <file>'), it uses the REST API with the same
  environment variables PARMA_URL, PARMA_USER and PARMA_PASSWORD and stops before any job is executed
  if one is missing.

  A <file> contains one or more definitions, either JSON or blocks like 'node { ... };'.
  See the directories in 'test/test_cmds' for examples.

  help
    get this help text.

Options (must precede the command):
  --admin
    log in as admin with PARMA_ADMIN_USER and PARMA_ADMIN_PASSWORD.
    Without this option PARMA_USER and PARMA_PASSWORD are used.

Configuration:
  curl.sh reads the url of the backend and the credentials ONLY from environment variables:
    PARMA_URL              url of the backend, e.g. http://localhost:8080
    PARMA_ADMIN_USER       login name of the admin user (used with '--admin')
    PARMA_ADMIN_PASSWORD   password of the admin user (used with '--admin')
    PARMA_USER             login name of the normal user
    PARMA_PASSWORD         password of the normal user

  The credentials are kept in env files with 'export KEY=value' lines:
    .env_testsetup  git-controlled. Contains ONLY the well known values of the test setup.
    .env            git-ignored. Contains the real passwords.
  'admin.sh init-datastore' sources one of them (default .env_testsetup, choose another one with
  'admin.sh init-datastore -e <file>') and sets PARMA_URL from the property file.
  If you call curl.sh directly, source an env file and set PARMA_URL in your shell first (see examples).
  Use a subshell '( ... )' to keep the passwords out of your interactive shell afterwards.

Notes:
  The file content is never put on the command line. The JSON request body is written to a temporary file
  and sent with "curl --data-binary @file", a plain file is sent as multipart form ("curl -F file=@...").
  Thus the size of the file can't break the curl command.
  To build JSON 'jq' is used, if available, otherwise python.

Examples:
  calling curl.sh directly with the test setup:
    source .env_testsetup
    export PARMA_URL=http://localhost:8080
    ./curl.sh --admin user test/test_cmds/sklearn/user.txt
    ./curl.sh node test/test_cmds/sklearn/node.txt
    ./curl.sh run test/test_cmds/sklearn/run.txt
    ./curl.sh data-file my.data.csv
    ./curl.sh snakemake-gen wf_seed_42_with_if:1
    ./curl.sh snakemake-run snakefile_wf_seed_42_with_if_1:latest 4

  with the real passwords, in a subshell:
    ( source .env; export PARMA_URL=http://localhost:8080; ./curl.sh node my_nodes.txt )

  calling curl.sh by admin.sh:
    ./admin.sh init-datastore                  upload the test setup (users, nodes, workflows, runs)
    ./admin.sh init-datastore -e .env          the same, credentials from .env
